## Реестр проблем и порядок исправления

**P1 · Две копии формул в Markdown/Quarto. Исправлено в профиле.** Плагин ii отправляет RGBA/PNG и размещает символы U+10EEEE в `plugins/ii.nvim/lua/ii/init.lua` (`decorate`, `M.render`). Одновременно в конфигурации `nvim/zx0r/lua/plugins/ui.lua` был включён `Snacks.image.math`. В отдельном Neovim с установленными парсерами и настройкой из профиля реальный `Snacks.image.doc.find` выбрал 13 формул для `showcase/01.md` и 14 для `showcase/02.qmd`. Первая формула QMD занимает исходные строки 9–14. После следующей правки результаты равны 0 и 0. Она влияет на формулы во всех форматах Snacks. Остальные функции просмотра изображений доступны.

```lua
-- Конфигурация snacks.nvim при использовании ii как обработчика математики
image = {
  enabled = true,
  math = { enabled = false },
},
```

**P1 · Повторная подготовка картинки после попадания в кэш.** В исходном `src/compose.rs::compose_document` каждый span вызывал `src/image.rs::render`, который уже отправлял результат в буфер через `stage`. При повторении id компоновщик укорачивал APC до прежней длины. Для удалённого транспорта это оплачивает PNG и Base64 повторно. Для локального транспорта имя уже созданного POSIX SHM исчезает из ответа, терминал не сможет открыть и освободить этот объект. Перенести проверку в момент непосредственно перед staging, сохранить все вхождения в раскладке, обнулять множество при новом кадре. Проверить два одинаковых span, одну передачу, две позиции и ровно одно новое имя SHM.

**P1 · Холодный рендер останавливает обслуживание сокета.** `src/daemon.rs::step_read_payload → dispatch_and_respond → render_response` выполняет компиляцию, чтение L2 и сжатие в потоке `poll`. Неблокирующие дескрипторы предотвращают ожидание готовности сокета, но длительная формула занимает поток целиком. Сначала измерить p95/p99 второго клиента при одновременном холодном рендере. При неприемлемой задержке передать тяжёлые задания одному рабочему потоку с ограничением очереди по байтам. Заголовок, поколение слота и возврат результата принадлежат реактору. Не добавлять Tokio или неограниченный пул задач.

**P1 · Лимит кадра применяется слишком поздно.** `src/ipc.rs::encode_dual_response` проверяет 64 MiB после наполнения APC/ANSI и блоков. `src/daemon.rs::handle_preview_file` проверяет 32 MiB для удержания готового кадра после композиции. Эти пороги не ограничивают пиковую память построения. Ввести отдельные бюджеты вывода и рабочего растра. Учитывать уже записанные байты и верхнюю границу следующего блока до увеличения буфера. Для Base64 использовать проверенную арифметику с учётом заголовков каждого фрагмента. Ошибка должна освободить частичный результат. Проверить RSS на документе с большим числом разных валидных формул.

**P1 · Обработчик файла может ждать до проверки типа.** В `src/daemon.rs::read_bounded_file` и `src/main.rs::read_file_bounded` тип проверяется после открытия пути. Использовать `OFlags::NONBLOCK` при открытии на чтение, затем `fstat` и допуск только обычного файла. Объединить чтение обычного файла в одну функцию с переданным буфером. Сохранить чтение stdin отдельным контрактом. Вход и выход проверки — типизированная ошибка и продолжающий отвечать daemon.

**P2 · Упаковка DecorateBuffer.** В `src/daemon.rs::render_response` каждый диапазон ANSI проходит через `to_vec`, для простых форматов копируется весь `out.ansi`, затем каждый блок переносится в новый `wrapped`, общий `text_buf` и finally в `slot.buf`. Один и тот же интервал исходника сканируется на переводы строк дважды. Смежные диапазоны ANSI уже принадлежат `ComposeOut`. Хранить только четыре числовых границы, объединять блоки на общей строке и записывать сразу в целевой буфер с резервом для длины. Проверка — побайтово прежний IXPC для пустого файла, inline, CRLF, notebook и неполной последней строки.

**P2 · Страница далеко от начала файла.** Каждый `PreviewFile` читает и хеширует весь файл в `src/daemon.rs::handle_preview_file`. `src/viewport.rs::append` отсчитывает визуальные строки от нуля; `src/compose.rs::append_visible_uploads` строит строку для каждого известного id и ищет её по целой странице. Добавить индекс визуальных строк и видимых id в уже подготовленное представление. Индекс хранит состояние стиля на точках входа. При сохранении контракта «тот же mtime, другой контент» чтение и проверку содержимого учитывать отдельно. Пропускать проверку можно только при явном токене снимка со стороны хоста.

**P2 · L1 сбрасывает все 64 слота.** `src/vram.rs::Cache::insert` суммирует capacity всех реплик и прибавляет размер новой, в том числе если выбранная реплика уже имеет подходящий буфер. При превышении бюджета 32 MiB очищается вся таблица. Сначала выбрать жертву PLRU, вычесть её прежнюю capacity; учитывать фактическую capacity после замены и освобождать дополнительные реплики только по необходимости. На цикле чередующихся наборов измерять hit ratio и удержанные байты.

**P2 · Диагностика и владение состоянием.** `src/raster.rs::draw_scene_svgs` молча пропускает SVG при отказе usvg; полностью прозрачный raster может получить успешный ответ. Lua-клиент трактует IXPC ERR как неверную команду. В `M.render` меняются опции окна до получения кадра, а на нескольких выходах по ошибке не восстанавливаются. Вернуть ошибку при отказе единственного графического объекта, сохранять читаемый исходник, декодировать ограниченное тело ERR после проверки корреляции и фиксировать причину в статусе окна.

**Удаление лишнего.** `src/vram.rs::Table` и `compute_tag` участвуют в тестах и микробенчмарке, рабочий путь `src/image.rs` использует BLAKE3 и `vram::Cache`. Перед удалением из публичной библиотеки проверить внешние вызовы. В бенчмарке измерять также рабочий cache hit с реальным транспортом. `src/tty.rs::render_ansi` и `src/compose.rs::crop_lines` — кандидаты на удаление отдельными изменениями после проверки потребителей. Для архивов `src/fmt/archive.rs::to_tree_with_palette` сначала строит табличный Scene, затем извлекает из него обратно имена. Выделить перечисление записей поверх среза и выводить дерево непосредственно из этого перечисления.

**Прокрутка ipynb в Yazi.** В исходной версии команда `seek 5` при высоте панели 40 строк перескакивала на 20 строк. Для каждой страницы сервер снова рассчитывал ширину всех предыдущих строк и пересылал графику, которую терминал уже показывал. Измерен исходный полный обмен с Unix-сокетом, ширина 64, высота 12, ячейка 9×18. В `03.ipynb` на смещении 12 ответ содержит 21 053 байта только графических команд. В `analysis.ipynb` страницы 0 и 12 обе содержат по 3040 байт графики. Измерение включает клиентский обмен и сборку кадра, запись терминалом измеряется отдельно. Выбран ленивый индекс с контрольной точкой каждые 32 визуальные строки. Точка хранит исходную позицию и состояние SGR. Инвалидация совпадает со сменой содержимого или геометрии.

**Публикация соседней страницы.** Исправление в `plugins/ii.yazi/main.lua` сохраняет на одну страницу набор целых успешно записанных передач, до 1 MiB. Только непосредственно запрошенный `seek` между перекрывающимися страницами того же файла, вкладки и геометрии разрешает пропустить побайтово идентичную передачу. Ячейки публикуются для каждой страницы. Обычный `peek`, возврат к файлу, смена ширины/темы, неперекрывающаяся страница и ошибка записи требуют полной публикации. Буфер продолжает получать актуальную страницу от Rust. Один `seek` теперь перемещается ровно на `job.units` визуальных строк.

## Контракт Kitty Graphics Protocol

`src/kitty.rs` формирует отдельную команду загрузки и виртуальное размещение `a=p,U=1`. Текст несёт id в RGB переднего плана. Совпадение id, строки и столбца с загруженным растром обязательно. Все 297 значений таблицы проекта сверены с файлом диакритик установленного Kitty 0.51.0. Neovim использует координаты каждой ячейки для частичной перерисовки; Yazi — начальную координату ряда и последовательные столбцы. `q=2` обязателен и в последующих фрагментах. Прозрачность задаётся альфой растра; RGB placeholder менять цветокоррекцией или палитрой из 256 цветов нельзя. Для Neovim нужен `termguicolors`; в проверенном профиле опция включена. [Спецификация KGP](https://sw.kovidgoyal.net/kitty/graphics-protocol/#unicode-placeholders)

Ограничения для следующего этапа: id выводится из хеша и сужается до 24 бит в `vram::Tag::image_id`. Коллизия может связать две разные картинки с одним цветом даже в двух окнах. Добавить управляемое разрешение коллизий в области жизни терминальной сессии или полный 32-битный id с третьей диакритикой и тест на принудительное совпадение младших битов. После столбца 296 функция `placeholder_row::<true>` переходит на наследование координаты. Для очень широких сплитов нужна проверка частичного redraw или ограничение ширины размещения. Запасным транспортом при отказе SHM служит PNG/Base64. Для production-превью дистанционное управление Kitty не требуется. Под tmux нужен разрешённый passthrough в самом мультиплексоре. Фактический путь пользователя через SSH/tmux отдельно от прямого запуска не подтверждён.

## Целевая схема и конкретные изменения

```text
путь / снимок буфера → ограниченный ввод → исходные диапазоны и нормализация
       → текст и графические диапазоны → пиксели по ключу содержимого
       → один upload на изображение в кадре + индекс визуальных строк
       → один ответ IXPC → проверка поколения в хосте → публикация через UI
```

**Сборка блока прямо в конечный буфер.** Ниже фрагмент предлагаемой замены промежуточного Vec на блок в `daemon::render_response`. Вызывать после объединения исходных диапазонов одной строки. При частичной записи отозвать весь формируемый ответ. Бюджет нужен внутри writer до выделения памяти.

```rust
let header = dst.len();
dst.extend_from_slice(&first_row.to_le_bytes());
dst.extend_from_slice(&end_row.to_le_bytes());
dst.extend_from_slice(&0u32.to_le_bytes());
viewport::append(&out.ansi[start..end], cols, 0, 0, dst);
let len = u32::try_from(dst.len() - header - 12).map_err(|_| Error::ResourceLimit)?;
dst[header + 8..header + 12].copy_from_slice(&len.to_le_bytes());
```

**Продолжение короткой записи.** Когда измерения оправдают отдельные сегменты header/APC/text, передавать их одним writev. Буферы принадлежат слоту до полного завершения; недопустимо ссылаться на общую scratch-память, которая изменится при следующем клиенте. Состояние слота — номер сегмента и байтовое смещение. При EINTR повторить; при EAGAIN сохранить состояние и ждать POLLOUT. Перед заменой сравнить с сегодняшней одной копией на коротких и больших ответах, включая двух медленных клиентов.

**Порядок внедрения и приёмки.**

1. Точность кадра. При одной геометрии сравнить положение, цвет-id и строки изображения в Yazi и Neovim. Проверить Insert/Esc, смену окна и полную перерисовку. Проверять внешний обработчик формул на реальных запросах Tree-sitter.
2. Горячий путь. Повторный span не создаёт SHM/PNG; видимый на соседней странице upload не повторяется при подтверждённом seek. Сравнить p50/p95/p99 UDS и фактические передачи в PTY, отдельно холодное открытие, перемотку и возврат назад.
3. Ограничения ресурсов. Ввести байтовые бюджеты на промежуточный результат, deadline активного слота, обработку ошибок SVG и IXPC. Для каждого отказа — сохранение исходника и следующий успешный запрос.
4. Удаление дубликатов. Начать с общих readers, упаковки блоков и дерева архива. Публичные символы удалять после поиска внешних потребителей и публикации изменения API. Объединять парсеры только с равным набором проверенных входов.
5. Конкурентность. Сравнить один реактор, один ограниченный worker и многопоточную схему по p99 независимого Ping во время холодного рендера, RSS и отмене устаревших результатов. Один worker оправдан при подтверждённом нарушении бюджета. Многопоточность на каждый span умножает scratch и усложняет порядок публикации.

macOS arm64, rustc 1.100.0, сборка release, Unix stream на отдельном сокете, Python monotonic timer.
